## 1. 主链路：一次流式共情对话

```mermaid
sequenceDiagram
  autonumber
  participant U as 用户端 U7
  participant G as SseController
  participant S as ChatService
  participant A as AuditService 前置词检
  participant E as EmotionService 级联
  participant R as RiskService
  participant L as Spring AI / DeepSeek
  participant D as MySQL + Redis
  U->>G: POST /api/ai/chat/stream {conversationId, content, style}
  G->>D: 校验会话归属 + 限流 AI 6/min
  G->>A: 用户输入送 DFA 检（黑名单直接拒，风险词打标）
  A-->>G: hitWords / riskTag
  G->>S: 通过 → 组装上下文（system 人设 + 最近 12 轮 + summary + 情绪档案）
  S->>E: level1 词典通道（< 5ms）
  Note over E: 命中且置信度 ≥0.55 → 直接出标签<br/>否则或含风险词 → level2 送 LLM 判别
  E->>L: 情绪判别（结构化 JSON 输出，flash）
  L-->>E: label / intensity / valence / confidence
  S->>R: 规则 + LLM 双通道定级 L0-L3
  alt L3（正在实施伤害 / 具体计划）
    R->>D: 立即建 alert_ticket(level=L3) + notify
    R->>U: 强制下发 /user/queue/alert → 求助卡片置顶 + 12356
    S-->>U: 模板接管话术（不给诊断、不给方法，只给出口）
  else L2（明显危机信号）
    R->>D: 建工单 L2，SLA 30min
    S-->>U: 正常共情回复 + 文末求助卡片（不打断）
  else L0/L1
    S->>L: 共情回复（流式，temperature 0.8）
    L-->>S: delta tokens
    S-->>U: SSE event meta → delta×N → done
  end
  S->>D: 落 chat_message（含 emotion_*、risk_level、tokens、latency）
  S->>D: 落 emotion_record（source=chat，被动记录）
  S->>D: 落 ai_call_log（scene/model/prompt_version/cost_cent/first_token_ms）
  S->>D: 更新 user_profile.risk_flag（只增不减，人工核实后才降级）
```

## 2. 降级链路（断网 / 无 Key / 超时的兜底，演示必考）

```mermaid
flowchart TD

  G --> H{"risk_level ≥ L2?"}
  H -- 是 --> I["危机链路不依赖 LLM：词典规则命中即建工单<br/>宁可误报不可漏报"]
  H -- 否 --> J["界面顶部常驻离线提示，不白屏不报错"]
  E -- 是 --> K["ai_call_log success=0 error 摘要<br/>连续 5 次失败 → 熔断 60s 直接走离线"]
```

## 4. 二次链路：发帖 → 审核 → 入池 → 推荐（需求 §6.2）

```mermaid
sequenceDiagram
  autonumber
  participant U as 用户端 U5
  participant P as PostService
  participant A as AuditService
  participant E as EmotionService
  participant Q as 审核队列
  participant O as 离线 Job
  participant F as Feed 接口
  U->>P: POST /api/posts {type, title, content, topics, is_anonymous}
  P->>A: DFA + 变体归一（全半角/插空格/emoji）
  alt 黑名单命中
    A-->>P: BLOCK → status=REJECTED + audit_task(source=machine)
  else 灰名单命中
    A-->>P: REVIEW → status=HUMAN_REVIEW（仅作者可见）+ 入队
  else 未命中
    A-->>P: PASS → status=MACHINE_REVIEW → LLM 复核（可选）→ PUBLISHED
  end
  P->>E: 正文情绪打标 → emotion_primary / emotion_score / risk_level
  P->>P: 写 post_status_log（from,to,operator,reason）
  P->>Q: 树洞帖设 auto_destroy_at（到期三处同时消失）
  O->>O: 定时刷新 topic.hot_score 与 item_similarity
  F->>O: 读 recommend_result（预计算）
  U->>F: GET /api/feed
  F-->>U: 情绪感知加权后的信息流
```

## 5. 关键时序约束（写进代码注释的性能红线）

| 编号 | 约束 | 取值 | 依据 |
|---|---|---|---|
| TS-1 | SSE 首字延迟 TTFT | ≤ 2 s（P95） | NFR2 |
| TS-2 | 情绪 level1 词典通道 | ≤ 5 ms，不阻断主流程 | §8.1.2 |
| TS-3 | 级联送 LLM 的触发条件 | conf < 0.55 或命中风险词 | §8.1.2 |
| TS-4 | L3 工单建立 | 与用户输入同事务内落库，异步只做通知 | FR10 |
| TS-5 | 审核 SLA | L2=30min / L3=5min，超时自动升级并通知 SUPER | §5.2 |
| TS-6 | 计数回写 | Redis 即时 + 5min 定时回写 DB，不在写请求里加行锁 | BR2 |
| TS-7 | 对话上下文窗口 | 最近 12 轮 + summary 压缩，超窗先摘要 | FR2.3 |
